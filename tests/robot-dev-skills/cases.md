# 机器人开发主入口触发回归用例

每条输入都是合成问题。每行对应一个专项，包含两种不同的触发方式。显式用例在问题前加 `$robot-dev-skills `，自然用例原样提交。每题独立开启只读 Codex 会话，测试项目不包含本表、评分条件或技能清单。Claude Code 的显式调用前缀是 `/robot-dev-skills `，需要在该宿主单独取证。

## 判分

- 工程请求须完成会话，工具输出中应看到主入口或选题表，以及首个选中专项的独有正文。文件路径出现在答案、文件清单或其他文档的链接中，都不单独计为读到正文。
- 同一次工具输出混有多个专项正文时，检查是否实际选择了正确主流程。同时批量打开多个指南不能算作唯一首选。专项明确要求的分支资料也要有读取记录。
- 网络、认证和进程启动错误另计，可以重试。保留首次路由失败和复测记录。模型直接算对工程结论但跳过入口，仍记未触发。
- 覆盖度统计每个专项是否有至少一个经验证的可用问法。显式和自然触发率分别按各自全部试验计算。

## 单题复跑

在没有项目技能和题库的空 Git 项目开启新会话，把问题作为标准输入。检查 JSONL 中成功的 `command_execution` 输出是否含对应专项的正文，再核对最终回答。保留输入、读取顺序、答案和运行错误。

```sh
printf '%s\n' '$robot-dev-skills 把真人走路片段迁到腿更短的机器人，支撑期脚尖在地上滑。如何验证骨架绑定和接触约束？' | codex -a never exec --ephemeral --sandbox read-only --disable multi_agent --json -
```


## 自动复跑

以下命令从仓库根目录运行。首条只校验题库和安装目录，第二条只跑一题的两种问法，第三条发起全部 118 个独立 Codex 请求。可用 `--output` 指定新的证据目录。边界行为按上表另行复核。选择 `--mode guided --case 45` 会在原自然问题前加上“请按本机的机器人开发指南处理以下问题，只打开当前交付物需要的专项。”，单独测试领域提示。

```sh
python3 tests/robot-dev-skills/run.py
python3 tests/robot-dev-skills/run.py --mode both --case 45
python3 tests/robot-dev-skills/run.py --mode both --workers 3
```
